## 🛠 Стек технологий

- **Apache Hive** (Cloudera CDH 5.11.2) на кластере МФТИ
- **Apache Hadoop HDFS** (хранение данных в формате Parquet)
- **Оконные функции и агрегации Hive** (`AVG`, `CASE WHEN`)
- **Формат хранения:** Parquet (таблица `kkt_transactions_parquet` из task2)
- **Bash** (скрипт запуска `run.sh`)

## 💡 Архитектура решения

Решение задачи — нахождение налогоплательщиков, у которых средняя прибыль одной транзакции в первой половине дня (до 13:00) строго больше средней прибыли одной транзакции во второй половине дня (после 13:00). Задача решается одним SQL-запросом с использованием вложенного подзапроса и условной агрегации через `CASE WHEN`.

### 🔹 Логика запроса (`00_task4-select-profit.sql`)

Запрос состоит из двух уровней вложенности:

**Уровень 1 — Вычисление средней прибыли утром и вечером:**

Разбор ключевых элементов:
- Извлечение часа из timestamp:
  - regexp_extract(dateTime, '(\\d{13})', 1) — извлекает 13-значный unix-timestamp в миллисекундах
  - CAST(... AS BIGINT) DIV 1000 — переводит миллисекунды в секунды
  - from_unixtime(...) — конвертирует в формат даты/времени Hive
  - hour(...) — извлекает час (0–23) из временной метки

- Условная агрегация через CASE WHEN:
  - CASE WHEN hour(...) < 13 THEN totalSum END — для утренних транзакций (00:00–12:59) берётся сумма, иначе возвращается NULL
  - CASE WHEN hour(...) >= 13 THEN totalSum END — для вечерних транзакций (13:00–23:59)
  - Функция AVG() автоматически игнорирует NULL значения, поэтому среднее считается только по нужным транзакциям

- Группировка по userInn — для каждого налогоплательщика вычисляются два средних значения

**Уровень 2 — Фильтрация и форматирование:**
- WHERE morning_avg > evening_avg — оставляем только тех, у кого утренняя прибыль строго больше вечерней
- AND morning_avg IS NOT NULL AND evening_avg IS NOT NULL — исключаем налогоплательщиков, у которых не было транзакций в одном из периодов (иначе сравнение было бы некорректным)
- ROUND(...) — округление прибыли до целых (по требованию условия)
- ORDER BY morning_profit — сортировка по утренней прибыли (по возрастанию, так как ASC по умолчанию)

### 🔹 Почему Parquet?
Используется таблица kkt_transactions_parquet, созданная в task2, потому что:
- Parquet показал наилучшую производительность (8720 мс) при сравнении форматов
- Колоночное хранение ускоряет агрегации AVG() и фильтрации по времени
- Меньший объём данных на диске → быстрее чтение с HDFS

### 🔹 Обработка edge cases
- NULL в dateTime — hour(from_unixtime(NULL)) вернёт NULL, условие CASE WHEN не выполнится, транзакция не попадёт ни в утреннюю, ни в вечернюю выборку
- NULL в totalSum — AVG() игнорирует NULL, поэтому такие транзакции не влияют на среднее
- Только утренние или только вечерние транзакции — одно из средних будет NULL, строка отфильтруется через IS NOT NULL
- Равенство утренней и вечерней прибыли — отфильтровывается условием > (строго больше)

### 🔹 Почему CASE WHEN внутри AVG, а не два отдельных запроса?
Использование одного запроса с условной агрегацией эффективнее двух отдельных запросов, потому что:
- Данные читаются с HDFS один раз, а не дважды
- Группировка по userInn выполняется один раз
- Меньше накладных расходов на запуск MapReduce-задачи
