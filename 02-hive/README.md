## 🎓 Чему я научился

Выполнение этих задач дало мне глубокое практическое понимание работы с большими данными в экосистеме Hadoop через Apache Hive. Вот ключевые навыки, которые я приобрёл:

###  Архитектура Apache Hive

- Понял принцип работы Hive как SQL-интерфейса над Hadoop: Hive транслирует SQL-запросы в MapReduce/Tez-задачи
- Научился создавать **внешние таблицы** (`EXTERNAL TABLE`), которые не управляют файлами на HDFS — данные остаются на месте, при `DROP TABLE` файлы не удаляются
- Освоил работу с **JsonSerDe** (`org.openx.data.jsonserde.JsonSerDe`) для парсинга JSON-файлов построчно и маппинга полей на колонки таблицы
- Понял разницу между **управляемыми** и **внешними** таблицами и когда какую использовать

### 🔹 Форматы хранения данных

- Создал таблицы в трёх форматах: **TEXTFILE**, **ORC**, **Parquet** — и сравнил их производительность на реальном запросе
- **Parquet** показал наилучший результат (8720 мс) — колоночное хранение эффективно для агрегаций
- **ORC** занял второе место (9140 мс) — также колоночный формат, но с другими оптимизациями
- **TEXT** показал худший результат (20850 мс) — в 2.4 раза медленнее Parquet, так как требует полного сканирования строк
- Понял, почему колоночные форматы быстрее: читаются только нужные колонки, лучшее сжатие, predicate pushdown

### 🔹 Оконные функции в Hive

- Освоил `ROW_NUMBER() OVER (PARTITION BY ... ORDER BY ...)` для ранжирования строк внутри групп (Task 3 — поиск наиболее прибыльного дня)
- Научился использовать **кумулятивные оконные функции** `SUM() OVER (PARTITION BY ... ORDER BY ... ROWS UNBOUNDED PRECEDING)` для отслеживания состояния во времени (Task 5 — поиск нарушений порядка транзакций)
- Понял разницу между `ROWS UNBOUNDED PRECEDING` (от начала партиции) и другими типами окон
- Освоил вложенные подзапросы с оконными функциями для многоуровневой обработки данных

### 🔹 Условная агрегация

- Научился использовать `CASE WHEN` внутри агрегатных функций (`AVG`, `SUM`) для условной обработки данных (Task 4 — сравнение утренней и вечерней прибыли)
- Понял, что `AVG()` автоматически игнорирует `NULL` значения, что позволяет элегантно разделять данные на группы без нескольких запросов
- Освоил паттерн "один запрос вместо двух" — данные читаются с HDFS один раз, а не дважды

### 🔹 Работа с JSON-данными

- Научился извлекать вложенные поля через точечную нотацию: `content.userInn`, `content.totalSum`

## 💡 Ключевой инсайт

> Hive — это не просто "SQL над Hadoop". Это мост между миром аналитиков (SQL) и миром распределённых вычислений (MapReduce/Tez). Правильно написанный Hive-запрос может быть в 2-3 раза быстрее на колоночных форматах (Parquet/ORC) по сравнению с текстовыми, а оконные функции позволяют решать задачи, которые в чистом MapReduce требовали бы нескольких проходов и сложной логики.

Эти задачи научили меня думать в терминах **распределённых систем** и **колоночного хранения**, а не просто писать SQL. Этот фундамент критически важен для перехода к более современным инструментам (Spark SQL, Presto, Trino), где те же принципы применяются, но с меньшим количеством рутинных операций и большей производительностью.
