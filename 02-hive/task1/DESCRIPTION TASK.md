## 🛠 Стек технологий

- **Apache Hive** (Cloudera CDH 5.11.2) на кластере МФТИ
- **Apache Hadoop HDFS** (хранение данных в `/data/hive/fns2`)
- **JsonSerDe** (`org.openx.data.jsonserde.JsonSerDe`) — десериализатор JSON-строк в колонки Hive
- **YARN** (управление ресурсами кластера)
- **Bash** (скрипт запуска `run.sh`)

## 💡 Архитектура решения

Решение задачи состоит из двух SQL-скриптов: создания внешней таблицы с парсингом JSON и выборки первых 50 строк для проверки корректности данных.

### 🔹 Шаг 1: Создание внешней таблицы (`00_task1-create-table-serde.sql`)

**Подключение JsonSerDe:**
sql
ADD JAR /opt/cloudera/parcels/CDH/lib/hive/lib/json-serde-1.3.8-jar-with-dependencies.jar;


- Библиотека `json-serde-1.3.8` позволяет Hive читать JSON-файлы построчно и мапить поля JSON-объекта на колонки таблицы
- Без этого JAR Hive не сможет распарсить вложенные JSON-структуры

**Настройки окружения:**

```sql
SET hive.cli.print.header=false;
SET mapred.input.dir.recursive=true;
SET hive.mapred.supports.subdirectories=true;
```

- recursive=true + subdirectories=true — позволяют Hive читать данные из вложенных поддиректорий в /data/hive/fns2 (данные разбиты по папкам)
- print.header=false — отключает вывод заголовков колонок (важно для корректной работы автотестов)

  
- Создание таблицы
- База данных создаётся автоматически на кластере (имя = логин в gitlab)
- DROP IF EXISTS обеспечивает идемпотентность скрипта
- JsonSerDe — парсит каждую строку файла как JSON-объект
- ignore.malformed.json = true — критически важная опция: в датасете есть некорректные строки, без неё запрос упадёт с ошибкой парсинга
- STORED AS TEXTFILE — исходные данные хранятся как обычный текст (по одной JSON-строке на строку файла)
- LOCATION '/data/hive/fns2' — указывает Hive, где лежат данные на HDFS


### 🔹 Шаг 2: Выборка первых 50 строк (01_task1-select-50.sql)
Преобразование dateTime:
- Поле content.dateTime в исходных данных хранится как строка вида "2017-06-15T10:30:45.123+03:00" или как unix-timestamp в миллисекундах
- regexp_extract(content.dateTime, '(\\d{13})', 1) — извлекает 13-значное число (timestamp в мс)
- CAST(... AS BIGINT) DIV 1000 — переводит миллисекунды в секунды
- from_unixtime(...) — конвертирует unix-timestamp в читаемый формат YYYY-MM-DD HH:MM:SS

Результат выполнения — таблица из 50 строк с колонками: номер ККТ, ИНН налогоплательщика, тип транзакции, сумма и дата

**📊 Почему именно такое решение?**

| Решение | Обоснование |
|-----------------------|----------------------------------------------------------------------------------------------------|
| EXTERNAL TABLE        | Данные уже лежат на HDFS в /data/hive/fns2, копировать их не нужно                                 |
| STRUCT для content    | Позволяет обращаться к вложенным полям через content.userInn без дополнительного парсинга          |
| JsonSerDe             | Стандартный способ работы с JSON в Hive; встроенный GET_JSON_OBJECT работал бы медленнее на больших объёмах|
| ignore.malformed.json | Обязательно — иначе первая же битая строка прервёт выполнение запроса                              |
|  recursive=true       |  Данные разбиты по поддиректориям, без этой настройки Hive увидит только файлы в корне             |

### 🔹Запуск

Через единый скрипт run.sh, который последовательно выполняет оба SQL-файла
