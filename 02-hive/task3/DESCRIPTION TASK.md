## 💡 Архитектура решения

Решение задачи — нахождение для каждого налогоплательщика наиболее прибыльного дня месяца. Задача решается одним SQL-запросом с использованием вложенных подзапросов и оконной функции `ROW_NUMBER()`.

### 🔹 Логика запроса (`00_task3-select-profit.sql`)

Запрос состоит из трёх уровней вложенности:

**Уровень 1 — Агрегация прибыли по дням:**
- REGEXP_EXTRACT(datetime, '(\\d{13})', 1) — извлекает 13-значный unix-timestamp в миллисекундах из поля datetime
- CAST(... AS BIGINT) DIV 1000 — переводит миллисекунды в секунды
- FROM_UNIXTIME(..., 'dd') — форматирует timestamp в день месяца (01–31)
- CAST(... AS INT) — приводит день к целому числу для корректной сортировки
- COALESCE(totalsum, 0) — заменяет NULL значения суммы на 0, чтобы не терять транзакции
- SUM(...) — суммирует прибыль по каждому налогоплательщику за каждый день
- GROUP BY userinn, day_of_month — группировка по налогоплательщику и дню

**Уровень 2 — Ранжирование дней по прибыли:**
- ROW_NUMBER() OVER (PARTITION BY userinn ...) — нумерует строки внутри каждой группы налогоплательщика
- ORDER BY profit DESC — самый прибыльный день получает номер 1
- day_of_month ASC — при равенстве прибыли выбирается более ранний день (детерминированный результат)

**Уровень 3 — Фильтрация топ-1 дня и форматирование:**
- WHERE rn = 1 — оставляем только самый прибыльный день для каждого налогоплательщика
- PRINTF('%.1f', ...) — форматирует прибыль с одним знаком после запятой (как в примере вывода)
- ORDER BY userinn ASC — сортировка по ИНН в лексикографическом порядке (требование условия для задач 3 и 5)

---
 
### 🔹 Почему Parquet?
Используется таблица kkt_transactions_parquet, созданная в task2, потому что:
- Parquet показал наилучшую производительность (8720 мс) при сравнении форматов
- Колоночное хранение ускоряет агрегации SUM() и фильтрации
- Меньший объём данных на диске → быстрее чтение с HDFS

### 🔹 Обработка edge cases
- NULL в datetime — отфильтрованы через WHERE datetime IS NOT NULL
- NULL в userinn — отфильтрованы через WHERE userinn IS NOT NULL
- NULL в totalsum — заменены на 0 через COALESCE(totalsum, 0)
- Равенство прибыли — при одинаковой прибыли у нескольких дней выбирается день с меньшим номером (day_of_month ASC)
