##  Стек технологий

- **Apache Hadoop 2.6.0** (Cloudera CDH 5.11.2) на кластере МФТИ
- **Hadoop Streaming** (Python 3.4.3)
- **MapReduce** (двухпроходный алгоритм)
- **YARN** (управление ресурсами кластера)
- **Bash** (скрипт запуска `run.sh`)

## 💡 Архитектура решения

Использован **двухпроходный MapReduce** с тегированием событий для анализа игровых сессий и подсчета средней смертности игроков. Задача требует агрегации событий по пользователям с последующим вычислением среднего значения и сортировкой.

### 🔹 Джоба 1: Парсинг логов и агрегация событий

**mapper1.py** — парсинг игровых логов и тегирование:
- Читает логи Minecraft сервера из `stdin`
- Использует регулярные выражения для поиска событий:
  - `UUID of player (\S+) is` → начало сессии игрока
  - `([a-zA-Z0-9_]+) died` → смерть игрока
- Фильтрует некорректные имена (начинающиеся с `/` или содержащие `:`)
- Эмитит теги:
  - `user \t SESSION \t 1` — для начала сессии
  - `user \t DEATH \t 1` — для смерти

**reducer1.py** — агрегация по пользователям:
- Группирует события по имени пользователя (ключ сортировки Hadoop)
- Накопляет счетчики:
  - `sessions` — общее количество сессий
  - `deaths` — общее количество смертей
- На выходе эмитит: `user \t sessions \t deaths`

### 🔹 Джоба 2: Вычисление среднего и сортировка

**mapper2.py** — identity mapper с валидацией:
- Читает агрегированные данные из первой джобы
- Валидирует формат: `user \t sessions \t deaths`
- Преобразует строки в целочисленные значения
- Обеспечивает чистоту данных для финального редьюсера (обработка `ValueError`, `IndexError`)

**reducer2.py** — вычисление смертности и топ-10:
- Для каждого пользователя вычисляет среднюю смертность: `avg = round(deaths / float(sessions), 2)`
- Пропускает пользователей с `sessions == 0` (защита от деления на ноль)
- Собирает результаты в список `results`
- Сортирует по составному ключу: `(-avg, user)` — сначала по убыванию средней смертности, при равенстве — лексикографически
- Выводит **топ-10** игроков с наивысшей смертностью

**Почему две джобы?**  
Разделение логики на две джобы позволяет:
1. **Первая джоба** — распарсить неструктурированные логи и агрегировать сырые события (SESSION/DEATH) по каждому игроку
2. **Вторая джоба** — вычислить производную метрику (среднее значение) и выполнить сортировку, что требует загрузки всех данных в память редьюсера

Это классический паттерн ETL в Hadoop: Extract & Transform (Job 1) → Aggregate & Sort (Job 2).
